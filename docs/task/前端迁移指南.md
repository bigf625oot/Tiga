# 前端任务接口迁移指南

## 背景
为统一平台内部多套任务引擎（Execution、Pathway、AsyncTasks）并提供一致的调度管理能力，后端对运行任务（TaskRun）的 API 进行了重构收敛。

## 变更说明

### 1. 运行任务主入口迁移
- **废弃**：`/api/v1/async/tasks` (未来版本将下线)
- **推荐**：`/api/v1/tasks`

目前 `/api/v1/tasks` 已完全兼容原 `async_tasks` 的全部接口定义（创建、列表查询、进度更新、WebSocket 实时推送等），前端可进行**零改动切换**。

#### 迁移步骤
1. 打开 `frontend/src/store/useTaskStore.ts`
2. 找到 `API_BASE` 与 `WS_BASE` 定义
3. 替换 URL 路径：
   ```typescript
   // 修改前
   const API_BASE = '/api/v1/async/tasks';
   const WS_BASE = `ws://${window.location.host}/api/v1/async/tasks/ws`;

   // 修改后
   const API_BASE = '/api/v1/tasks';
   const WS_BASE = `ws://${window.location.host}/api/v1/tasks/ws`;
   ```

### 2. 任务模板/模式管理 (TaskMode) 接口更名
如果您后续要调用原 TaskMode 相关的接口（如 `/api/v1/task-mode/tasks`）：
- **废弃**：`/api/v1/task-mode`
- **推荐**：`/api/v1/task-templates`

### 3. 支持高级分发 (Task Engine)
新的 `/api/v1/tasks` (POST) 接口底层已接入 `TaskEngineService` 分发器。
通过传入不同的 `task_type`，平台可将任务调度至不同底层引擎：
- `task_type="GENERAL"` (或空)：走通用异步处理
- `task_type="EXECUTION"`：走带有子任务拆分的 Execution 引擎
- `task_type="PATHWAY"`：走后台独立进程的流水线作业引擎
- `task_type="CELERY"`：走横向扩展的 Celery 分布式消息队列（需要后端已安装启动 Celery Worker）

### 4. 从模板一键发起运行 (Template to Run)
平台现已支持从“任务模板 (TaskTemplate)”直接创建并运行任务实例。前端只需调用：
- `POST /api/v1/task-templates/{task_id}:run`

调用该接口后，后端会自动读取模板配置，生成一条对应的 TaskRun，并投入 `TaskEngineService` 进行调度。
返回结构与 `POST /api/v1/tasks` 一致（包含 `task_id`），后续即可使用该 `task_id` 通过 WebSocket 或列表接口追踪进度。

> 提示：TaskCenter 会通过 WebSocket 自动收到上述各类引擎推回来的统一进度事件。
