1. 比例映射功能（The Mathematical Engine）
这是组件的“大脑”，负责将长列表的滚动像素转化为右侧小条上的位置。
实现原理：
滚动比例计算： scrollRatio = scrollTop / (totalHeight - viewportHeight)。得到一个 0 到 1 之间的值。
位置映射： 滑块的 top 值 = scrollRatio * (轨道总高度 - 滑块自身高度)。
代码体现： 就是你代码里的 thumbTop 计算属性。它确保了无论列表多长，滑块都能在轨道内“顶到头、踩到底”。
2. 滑块拖动交互（The Scrubber Drag）
这是复刻 AI Studio 体验最难的部分，它必须支持“全局捕获”。
实现原理：
三段式事件： mousedown (在滑块上按下) -> mousemove (全局监听) -> mouseup (全局移除)。
全局监听： 必须在 document 上监听 mousemove。这样即使用户鼠标在拖动时移出了那根细细的条，拖动依然有效且平稳。
反向计算： 拖动时，根据鼠标移动的 deltaY，反向算出列表应该滚动的 scrollTop，并通过 emit 通知父组件修改列表位置。
3. 锚点分布与跳转（The Anchor Markers）
这些是轨道上的小圆点，代表对话的轮次。
实现原理：
数据定位： 遍历消息数组，找出所有 role: 'user' 的消息。
百分比排布： 根据该消息在数组中的索引位置（或实际高度位置）计算出一个 topPercent。
精准跳转： 点击圆点时，调用父组件的 scrollToIndex。
关键点： 处理虚拟列表。如果目标消息还没渲染到 DOM 里，需要先通过虚拟列表的 API 跳转到大致位置，等 DOM 渲染后再进行微调补偿。
4. 视觉反馈与悬浮预览（Visual & Tooltip）
提升精致感的细节。
实现原理：
状态联动： 通过 isDragging 和 isHovering 两个变量切换 CSS 类名。拖拽时滑块变宽（从 4px 变 8px），轨道变亮。
内容预览： 当鼠标悬停在 Marker（圆点）上时，显示一个 absolute 定位的 div，展示该轮对话的文本摘要（label）。
CSS 优化： 使用 pointer-events: none 让背景容器不干扰点击，只有滑块和圆点设置为 pointer-events: auto。
5. 滚动自适应（The Auto-Sync）
当内容动态增加（如 AI 正在打字输出）时，滚动条要自动反应。
实现原理：
高度监听： 使用 useResizeObserver 监听列表容器。只要 AI 的回复让内容变长了，totalHeight 就会更新，从而触发滑块缩短或位置下移。
边界处理： 如果用户正在最底部，滑块会固定在轨道底端；如果用户向上翻看，滑块会停留在原位，但长度会随内容增加而微变。
