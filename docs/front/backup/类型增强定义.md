1. 类型定义增强 (Refine Schema)
请在保持现有结构的基础上，重点补充和优化以下定义：
多模态输入支持：在 ContentBlock 中增加 ImageBlock (支持 base64/url/upload 来源)。
对话树与版本：为 Message 增加 parent_id、version (number) 以及 is_truncated 字段，以支持重新生成和上下文管理。
流式增强：在 ToolCallBlock 中增加 raw_arguments: string，用于存储尚未完成 JSON 解析的流式增量字符串。
Human-in-the-loop：完善 ConfirmationBlock，增加 action_id 和完整的审批状态流（pending | approved | denied | expired）。
引用与溯源：增强 SearchSource 和 MessageSource，增加 snippet (摘要)、index (引用索引) 和 publish_date。
元数据统计：在 Message 中增加 metadata 字段，包含 usage (Token 消耗)、latency_ms (响应耗时) 和 finish_reason。
用户反馈：定义 MessageFeedback 类型（包含赞/踩、理由标签、详细评语）。
2. 核心逻辑实现要求
Discriminated Unions 辨识联合类型：确保在处理 ContentBlock 时，TypeScript 能够通过 type 字段进行完美的类型收窄。
类型守卫 (Type Guards)：为每一种 Block 编写 isThoughtBlock、isToolCallBlock 等判断函数。
流式解析器 (Streaming Parser)：
设计一个解析逻辑，能够处理后端推送的增量 StreamEventItem。
特别注意：当 thought 或 tool_call.arguments 处于 streaming 状态时，如何平滑更新对应的 Block 状态。
组件映射映射 (Component Mapping)：建立一个从 BlockType 到 React 组件名的映射关系表，为后续 UI 开发做准备。
3. 交互状态约束
Thought 状态机：思考块必须支持 thinking (打字机动画) -> expanded (默认显示) -> collapsed (用户手动收起) 的切换。
Plan 状态机：PlanStep 的状态更新必须是响应式的，当某个步骤从 running 变为 completed 时，UI 需要有明确的视觉反馈。
错误边界：实现 ErrorBlock 的重试逻辑定义，区分“可重试错误”和“不可恢复错误”。
4. 交付产物
src/types/chat.ts: 完整、加注释的增强版 TypeScript 类型文件。
src/utils/type-guards.ts: 用于判断 Block 类型的工具函数。
