# 秒懂-全链路判分规则（启发式）

本规则用于把“语言/语义理解能力”的可观察信号，转成可自动化复现的检查项。它不是“正确答案判定器”，而是把失败定位到更可解释的维度，便于做系统性排查与回归。

## 评分方式

- 每个用例配置若干 `checks`
- 每个 `check` 为布尔判定（通过/失败）
- 用例得分 = 通过数 / 检查数 × 100
- 用例结果：全部通过为 PASS，否则 FAIL

## 检查项列表

### 结构化与表达

- `has_sections`：输出具备 2+ 个清晰分段（标题/编号/关键板块）
- `has_action_items`：包含可执行行动项/下一步，并以条目形式列出
- `has_markdown_table`：输出 Markdown 表格（含分隔行）且行数充足
- `has_numbered_outline`：PPT/大纲类输出存在 5+ 条编号结构
- `has_directory_structure`：包含目录树/路径结构表达
- `outputs_markdown_mindmap`：以 Markdown 层级列表形式输出“脑图”结构

### 信息缺口与主动引导

- `asks_for_missing_info_or_placeholders`：对缺失信息提出问题或用占位符标注
- `asks_clarifying_questions`：在信息不全场景提出 2+ 个澄清问题
- `asks_time_clarification`：对“下午闹钟”等缺省条件主动追问具体时间
- `asks_user_goal_or_constraints`：对用户目标/约束提出澄清（用于消歧）

### 场景要素覆盖

- `has_meeting_essentials`：会议通知覆盖 时间/地点/参会人/议程/会前准备 4+ 项
- `has_interview_structure`：面试准备覆盖 自我介绍/追问/案例/要点 等要素
- `has_day_by_day_plan`：旅行规划包含 5+ 天按天安排
- `has_4week_plan`：训练计划包含周维度（至少覆盖 3 周标识）
- `mentions_health_risk_warning`：旅行/健康场景包含风险提示（如高反/就医阈值）
- `mentions_seek_medical_help_threshold`：健康科普明确“必须就医/急诊”的触发条件

### 技术任务质量

- `has_architecture_choice`：脚手架/选型输出包含 2+ 个明确技术选型点
- `gives_common_causes`：排障输出覆盖常见原因（flex/grid/overflow/viewport 等）
- `returns_refactored_code`：重构题给出代码块并提供改写版本
- `explains_changes_concisely`：重构题说明改动点/原因（不要求长篇）
- `contains_regex_like`：正则题输出包含关键正则特征（如 ^、(?=、\\d 等）
- `mentions_rule_limitations`：对“正则难以单独实现”的规则给出限制说明或补充校验建议
- `has_step_by_step`：环境/部署类输出具备 4+ 条可执行步骤
- `mentions_windows_considerations`：提及 Windows/CUDA/驱动/WSL 等关键约束

### 语义理解与约束遵守

- `disambiguates_pronoun`：能把“那个”正确回指到 Python/Java 等上文实体
- `explains_metaphor`：能解释隐喻语义，并转为现实语境建议
- `gives_actionable_advice`：给出 3+ 条可执行建议或明确“下一步”
- `does_not_mention_cloudnative`：严格不出现“云原生”字样
- `switches_to_indexing_architecture`：意图纠偏后切换到索引/去重/更新/合规等主题
- `single_sentence`：满足“一句话”限制（句子数≤1 且行数≤2）
- `addresses_constraint_conflict`：在矛盾约束下明确说明权衡/限制
- `uses_prior_context`：能引用前文上下文（如首屏慢/接口慢）来回答“优化”
- `provides_optimization_plan`：给出可执行的优化/排查方案
- `flags_false_premise_or_asks_for_evidence`：指出“你并未提到/信息缺失/需确认依据”，而不是盲从虚假前提

### 内容特征（弱检查）

- `tone_not_too_formal`：避免过于官腔且带有更自然语气
- `mentions_multiple_named_items`：竞品对比中提及 3+ 个常见工具名
- `mentions_compliance`：提及合规/版权/robots/条款/风险等要点
- `has_executable_plan`：惊喜方案包含时间流程（上午/当天/步骤等）
- `has_multiple_variants`：提供 3 套备选方案或明确“三套”
- `uses_analogy_and_caveats`：类比解释同时强调“类比≠事实”的边界
- `avoids_obvious_misconceptions`：避免明显误导（如“超光速传信息”）
- `is_interactive`：口语场景以服务员开场并等待用户继续（短输出+问句）
- `does_not_continue_without_user`：不抢跑演出双方多轮对话
- `outputs_polished_text`：润色邮件输出包含完整邮件结构
- `tone_professional`：润色邮件使用更礼貌正式措辞
