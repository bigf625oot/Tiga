建议的目录结构
eah_agent/
├── core/                # 核心引擎 (NLU, Dispatcher, Base Classes)
├── handlers/            # 【原 agents 文件夹】四种模式的业务入口
│   ├── quick_handler.py # 处理快问快答
│   ├── plan_handler.py  # 处理自规划 
│   ├── team_handler.py  # 处理 Team 协作逻辑
│   └── flow_handler.py  # 处理 Workflow 逻辑
├── agent/               # 单体 Agent 的具体定义/配置
├── team/                # Team 的具体成员编排定义
├── workflows/           # Workflow 的具体步骤定义
├── domain/              # 领域模型 (Prompt)
├── tools/               # 原子工具
├── skills/              # 复合技能
└── ...

目录划分的逻辑：
1. API层：负责接收 HTTP 请求，解析参数，调用核心引擎处理，最后返回 SSE 流。具体文件为 api/endpoints/chat.py
2. core负责“怎么转”（底层的驱动、意图识别）。
- 2.1 NLU：负责将用户输入转换为结构化的意图表示。
- 2.2 Dispatcher：负责根据意图调用相应的业务逻辑。
- 2.3 BaseAgent：定义 Agent 的基础行为，包括运行、处理消息、调用工具等。
3. handlers 负责“怎么接”（四种模式的业务入口）。
- 3.1 quick_handler.py：处理快问快答模式。
- 3.2 plan_handler.py：处理自规划模式。
- 3.3 team_handler.py：处理 Team 协作模式。
- 3.4 flow_handler.py：处理 Workflow 模式。
4. agent/team/workflows 负责“是什么”（具体的 Agent 提示词、团队成员、流程步骤）。
- 4.1 agent/：单体 Agent 的具体定义/配置。
- 4.2 team/：Team 的具体成员编排定义。
- 4.3 workflows/：Workflow 的具体步骤定义。
4.tools/skills 负责“能做什么”（插件和业务函数）。
- 4.4 tools/：原子工具的具体实现。
- 4.5 skills/：复合技能的具体实现。

原则：
1. 保证已有功能的正常运行。
1. 保持模块之间的职责清晰，避免模块之间的循环依赖。
2. 每个模块都有其特定的功能，不要将不同功能的代码混杂在一起。
3. 及时进行代码 review，确保代码质量和可维护性。

改造接口契约：
1. 定义 Handler 协议：首先在 core 中定义 BaseHandler 接口，确保 Dispatcher 能够以多态方式调用不同的业务模式。
2. 统一流式协议：将 SSE JSON 格式化与 think/tool 事件规范化下沉到 core（例如 core/stream_processor.py + core/stream_normalizer.py），作为全局唯一的输出格式转换器。
3. 配置驱动 Agent 创建：在 core/agent_manager.py 中实现工厂模式，根据 domain/ 中的配置文件（Prompt 模板、工具清单）动态构建 Agno 实例。
4. Skill/Tool 注册制：所有的 skills/ 和 tools/ 必须实现标准的注册接口，方便 Agent 动态加载。
5. 存量兼容：重构的第一步是建立新旧系统的桥接，通过 eah_agent.core.control_plane 作为新入口，HTTP 层仅保留 SSE 映射，业务逻辑逐步收敛到新架构。
