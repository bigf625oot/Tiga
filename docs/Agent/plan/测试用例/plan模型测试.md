PlanHandler 系统化调试测试用例文档 (v1.0)
一、 任务规划与指令合成 (Task Planning & Synthesis)
基础任务识别测试：输入简单的单步指令（如“查询北京天气”），验证系统是否能跳过复杂规划逻辑，直接生成单一执行步骤并正确输出状态流。
多步骤依赖拆解测试：输入涉及先后逻辑的任务（如“先搜竞品价格再写分析报告”），验证 AgentWorkflowEngine 生成的计划是否包含正确的先后依赖关系（DAG）。
模糊目标引导测试：输入极其模糊的指令（如“帮我搞定这个”），观察 _enrich_goal 合成的指令是否能引导 Agent 主动询问细节或生成“需求确认”步骤。
指令优先级覆盖测试：在 BaseHandler 中设置冲突的指令，验证 instructions 合成逻辑是否优先保证了系统级指令的权威性。
意图参数融合测试：通过 IntentResult 注入特定参数（如紧急程度），验证最终发给引擎的任务描述中是否包含了这些增强提示（Extraction Hints）。
超长任务书压力测试：输入超过 5000 字的详细任务说明，测试 PlanHandler 在处理大规模文本输入时的内存占用及 Token 窗口预留是否正常。
逻辑死循环检测测试：输入具有逻辑矛盾的任务（如“A 依赖 B 且 B 依赖 A”），验证引擎是否能在规划阶段识别出循环依赖并抛出合理错误。
任务目标增强验证：检查 _enrich_goal 函数输出的字符串，确认其是否包含了强制性的“遵循依赖感知协议”的 Mission 描述。
二、 资源并行装配 (Resource Assembly Parallelism)
组件并行启动测试：通过日志时间戳记录，验证 Agent 装配、文件处理和历史压缩这三个任务是否真正实现了异步并行启动（Non-blocking）。
Agent 装配失败隔离测试：模拟 AgentAssembler 在构建时抛出异常，验证 asyncio.gather 是否能正确捕获错误并触发 PlanHandler 的全局错误处理。
大规模历史压缩测试：提供超过 100 条的历史对话，验证 ContextCompressor 是否被正确触发，且压缩后的摘要是否被合入最终指令。
图谱记忆融入测试：针对具有知识图谱背景的 Session，验证 _get_history_messages_with_graph 是否成功提取了实体关联并丰富了上下文。
装配器参数传递测试：验证 _assemble_plan_agent 调用时，reasoning_override 和 enable_plan_tools 等关键参数是否准确传递给了组件。
资源就绪同步测试：模拟文件处理极慢的情况（延迟 10s），验证 Handler 是否严格等待所有 Task 完成后才进入 AgentWorkflowEngine 的执行阶段。
数据库 Session 稳定性测试：在装配任务执行期间模拟数据库连接瞬时抖动，测试 Handler 对 AsyncSession 的重试或报错机制。
三、 多模态与文件上下文 (Multi-modal Context)
单文件关联分析测试：上传一个 Excel 报表并提问，验证指令中是否准确注入了 "Environment Context (Files)" 以及文件的元数据。
多格式文件混合测试：同时上传 PDF、图片和文本文件，验证 FileOrchestrator 返回的 media 对象是否被完整传递给工作流引擎。
空内容文件容错测试：上传一个 0 字节的文件，验证系统是否能优雅跳过解析而不会中断整个规划流程。
文件上下文截断测试：上传超过 50MB 的超大文本文件，验证系统是否实现了合理的上下文截断，防止 LLM 输入溢出。
多模态目标对齐测试：任务要求“根据图片内容写代码”，验证生成的 Plan 第一步是否为“解析/视觉识别图片内容”。
文件解析失败路径测试：模拟文件解析引擎崩溃，验证 Handler 是否能向用户反馈“上下文受限”的状态信息。
历史文件引用测试：在对话中引用之前的历史文件，验证 prepare_history 是否能找回历史文件上下文。
四、 工具执行与沙箱调用 (Tools & Sandbox)
Python 沙箱代码执行测试：任务要求进行复杂数学计算，验证引擎是否能调用 E2B/Python 插件并在隔离沙箱内得出正确结果。
沙箱产物回调测试：任务要求生成一张数据图表，验证沙箱内生成的图片文件是否能作为 event 返回并展示下载链接。
外部网络搜索测试：任务涉及实时信息（如“今日股价”），验证 Agent 能否正确调用搜索工具并解析返回的 HTML/JSON 结果。
工具权限边界测试：尝试诱导 Agent 执行敏感命令（如删除文件），验证沙箱或工具层是否设置了严格的 syscall 拦截。
工具调用超时测试：模拟外部工具响应超过 30 秒，验证引擎是否具备超时熔断机制以及是否会尝试重新规划。
多工具链式调用测试：任务要求“搜索 -> 总结 -> 存为文件”，验证上一个工具的输出是否能作为下一个工具的准确输入（Data Flow）。
沙箱环境清理测试：验证任务结束后，沙箱内产生的临时进程和敏感数据是否被物理清除，确保多租户隔离安全。
工具返回格式容错测试：模拟工具返回了非预期的脏数据，验证 Agent 是否具备解析健壮性或自我纠错能力。
五、 工作流引擎状态机 (Workflow Engine Logic)
动态重新规划测试：在执行中模拟环境变化（工具报错），验证 update_plan 拦截器是否被触发以生成备选路径。
最大迭代步数限制测试：针对发散性任务，验证引擎是否在达到最大步数限制（如 10 步）时强制停止，防止 Token 无限消耗。
执行状态实时同步测试：验证异步生成器 yield 的每一个 event 类型是否包含正确的 status 和 content 字段供前端渲染。
并行分支合并测试：生成一个包含两个并行独立步骤的 Plan，验证引擎是否能同时启动这两个任务并等待汇总后再执行下一步。
DAG 持久化恢复测试：在执行中途强行中断进程，验证数据库中是否记录了当前计划状态，以及重启后是否能继续未完任务。
用户中断信号响应测试：在工作流运行期间模拟用户点击“停止”，验证 start_workflow 是否能接收取消信号并清理后台 Task。
复杂任务总结生成测试：在所有步骤完成后，验证引擎是否汇总了全量执行日志并生成了最终的 Answer。
六、 异常处理与鲁棒性 (Error Handling & Resilience)
LLM API 限流回退测试：模拟 OpenAI/Anthropic 接口返回 429 错误，验证系统是否执行了指数退避重试逻辑。
非法 JSON 响应测试：模拟 LLM 返回了格式错误的规划 JSON，验证引擎是否通过 repair_json 或重新 Prompt 进行了修复。
关键路径异常捕获测试：人为在 AgentWorkflowEngine 内部抛出 RuntimeError，验证 Handler 是否产出了“Planning engine encountered a critical failure”的友好提示。
国际化语言包测试：切换系统语言为英文，验证“Orchestrating...”等硬编码提示语是否正确经过 _() 函数进行了翻译。
数据库 Session 溢出测试：在高并发下压测 PlanHandler，验证每个请求的 AsyncSession 是否在 yield 结束后正确释放。
并发 Session 冲突测试：同一用户快速点击多次发送，验证系统是否具备防抖锁机制，防止同一会话产生多个规划引擎实例。
异步生成器退出测试：模拟客户端提前关闭连接，验证 process 函数的 finally 块是否正确清理了正在运行的异步任务。
七、 安全性与边界场景 (Security & Edge Cases)
提示词注入防御测试：输入带有“忽略之前所有指令”的任务，验证系统指令（SYSTEM_INSTRUCTIONS）是否保持了对 Agent 的最高控制权。
沙箱内存超限测试：运行一段申请大量内存的 Python 代码，验证沙箱是否设置了 OOM（内存溢出）限制并安全报错。
空输入参数边界测试：在 kwargs 缺失 session_id 或 db 时调用 process，验证系统是否在第一阶段就进行了断言保护。
历史消息污染测试：在历史对话中注入虚假的任务执行成功反馈，验证 Agent 是否能通过当前的 enriched_goal 识别真实状态。
Unicode 与特殊字符测试：输入包含表情符号、复杂的数学公式或非拉丁语系文字，验证全链路（Handler -> LLM -> Engine）是否存在编码乱码。
端到端完美路径集成测试：提供一个包含 2 个文件、3 个子任务、涉及代码计算和联网搜索的复合任务，验证系统是否能完成从规划到执行的 100% 自动化闭环。
