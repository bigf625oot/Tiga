集群一：复杂逻辑与动态规划（Thought & Plan Step）
测试重点：Agent 的大脑是否清醒，步骤是否同步。
场景：多阶段追问 —— 用户问“对比 A、B 两款手机，并根据我的预算推荐”。
链路： Thought (分析参数) -> Plan (1.搜A 2.搜B 3.对比) -> Tool -> Content。
调试点： 当 Plan 执行到第 2 步时，前端进度条是否实时变亮？
场景：计划修正 —— 搜 A 发现停产，Agent 自动修改 Plan 增加“寻找替代品”。
链路： Plan 动态增删。
调试点： 前端 Plan 列表是否平滑插入新步骤，还是会闪动报错？
场景：超长思考过程 —— 用户要求写一部 5000 字的小说大纲。
链路： 极长的 Thought 文本流。
调试点： Thought 区域是否自动出现滚动条，且不遮挡下方的 Content。
场景：无动作直接回复 —— 问“你好”。
链路： 仅 Thought -> Content（Plan/Tool 为空）。
调试点： 前端是否自动隐藏空组件，不留白。
场景：递归思考 —— 解决复杂数学题，思维链嵌套。
调试点： 验证后端 thought 字段中的换行符在前端是否正确解析为分段。
场景：计划依赖执行 —— 步骤 2 必须依赖步骤 1 的结果。
调试点： 模拟步骤 1 极慢，验证前端加载状态是否一直保持。
场景：任务取消 —— 在 Plan 执行到 50% 时点击“停止”。
调试点： 后端是否杀掉进程？前端是否保留已生成的 Plan 状态并显示“已取消”？
场景：静默思考模式 —— 后端只发 Thought 不发 Content。
调试点： 前端是否有“AI 正在思考中...”的占位提示，防止页面空屏。
场景：Plan 描述过长 —— 步骤标题超过 100 字。
调试点： 前端 Plan 列表是否折行，是否会挤压右侧内容。
场景：混合输出 —— 边思考边输出第一段话。
调试点： 验证前端 Thought 和 Content 两个容器是否能同时接收流数据。
集群二：实时搜索与信息整合（Web Search）
测试重点：外部数据的时效性与渲染准确性。
场景：热点新闻搜索 —— 搜“今天早上发生的 XXX 事件”。
链路： Search -> 返回多条结果 -> Content。
调试点： Search 卡片上的“发布时间”是否与后端抓取的原始数据一致。
场景：搜索来源重叠 —— 多个搜索结果指向同一域名。
调试点： 验证后端去重逻辑，前端是否只显示一个域名图标。
场景：搜索无结果 —— 搜一个不存在的乱码词。
调试点： 后端返回空数组，前端是否显示“未找到相关网页”提示而非白屏。
场景：搜索预览异常 —— 搜索结果包含非法 URL。
调试点： 前端点击卡片是否做了协议校验（防止跳转 javascript: 脚本）。
场景：图片搜索结果 —— 搜索结果带预览图。
调试点： 图片加载失败时，前端是否显示优雅的默认占位图。
场景：极多搜索结果 —— 返回 20 条搜索源。
调试点： 前端搜索区域是否提供“查看更多”按钮，避免页面拉得过长。
场景：搜索结果摘要缺失 —— 某个结果只有标题没摘要。
调试点： 前端布局是否塌陷。
场景：引用映射错误 —— 正文标注 [5]，但搜索结果只有 3 条。
调试点： 前端点击 [5] 是否有容错逻辑（如跳转到最后一条或提示错误）。
场景：搜索内容安全拦截 —— 搜索结果包含暴力内容。
调试点： 后端过审系统拦截，前端是否同步显示“根据政策不予展示”。
场景：搜索耗时监控 —— 模拟搜索接口延迟 10s。
调试点： 前端搜索卡片是否显示“正在搜索...”骨架屏。
集群三：内部知识库检索（KB Retrieval）
测试重点：精准匹配与文档归因。
场景：跨文档检索 —— 提问涉及两份不同的 PDF 文档。
调试点： 前端 KB 列表是否能区分来源，显示不同的文档标签。
场景：高分匹配片段 —— 检索到 99% 相似的内容。
调试点： 前端是否对该片段有特殊视觉标记（如“高匹配度”）。
场景：表格数据检索 —— 知识库中是一个 Markdown 表格。
调试点： 片段预览区域是否能渲染出微型表格，而不是乱码。
场景：引用定位 —— 点击引用 [1]。
调试点： 验证全链路 ID 是否透传，前端能否在 KB 面板中定位并高亮对应文本。
场景：文档过期 —— 检索到的文档在后端已被物理删除。
调试点： 前端点击查看原文档时，是否有友好的 404 提示。
场景：多语言 KB —— 检索到英文文档回复中文。
调试点： 验证 kb_retrieval 字段中的原始英文片段在前端不出现乱码。
场景：切片长度极端 —— 检索到一个 5 字的片段和一个 1000 字的片段。
调试点： 前端卡片高度是否自适应。
场景：无权限访问 —— 检索到用户无权查看的 KB。
调试点： 后端是否在返回流中自动脱敏，前端不显示敏感 ID。
场景：知识库版本切换 —— 验证同一问题在不同版本知识库下的检索结果差异。
场景：KB 命中率显示 —— 显示当前回答参考了多少百分比的私有知识。
集群四：工具调用与动作执行（Tool Call）
测试重点：输入输出的闭环。
场景：Python 绘图 —— 要求“画一个正弦曲线图”。
链路： Tool (Python) -> 生成图片 Base64 -> Content。
调试点： 前端 Tool 结果区能否直接渲染图片，而非显示乱码。
场景：数据库查询 —— “查一下上季度销售额”。
调试点： 验证 Tool 参数（SQL 语句）在前端是否以代码高亮形式展示。
场景：工具执行失败 —— Python 脚本语法错误。
调试点： 后端捕获 Error，前端 Plan Step 变红，并显示错误堆栈。
场景：需要确认的工具 —— 执行“删除文件”操作。
调试点： 后端暂停流，前端弹出确认框，确认后再继续发送 SSE 请求。
场景：大 JSON 结果输出 —— 工具返回 500 行 JSON 结果。
调试点： 前端 Tool 区域是否支持点击“展开/折叠”查看原始 JSON。
场景：多参数工具调用 —— 工具需要 5 个必填参数。
调试点： 验证模型生成的参数名与后端 API 定义是否完全一致。
场景：外部 API 超时 —— 查天气 API 挂了。
调试点： 验证全链路重试机制。
场景：格式化输出工具 —— 工具返回 HTML 片段。
调试点： 前端是否进行了 XSS 过滤。
场景：敏感操作审计 —— 记录谁在什么时间调用了什么工具。
调试点： 验证响应中是否包含审计 ID。
场景：工具链式响应 —— 工具 A 输出给工具 B。
调试点： 前端是否依次展示两个 Tool 执行卡片。
集群五：协议、边界与异常（Systematic Stress）
测试重点：全链路的坚韧性。
场景：SSE 消息乱序 —— 模拟后端先发了 Content 结尾，又发了 Tool 开始。
调试点： 前端是否有状态机管理，能重新正确排序展示。
场景：网络抖动重连 —— 流式传输中途断网 2s。
调试点： 前端重连后，页面是否能保留已生成的 Thought 和 Plan，不刷新清空。
场景：移动端窄屏压力 —— 在 320px 宽度下运行。
调试点： 复杂的 Plan Step、Tool JSON、KB 片段是否层叠错乱。
场景：深色模式实时切换 —— 正在生成时切换系统主题。
调试点： 代码块背景、搜索卡片边框是否同步更新，无残影。
场景：快速连续提问 —— 第一条还没回完，立马发第二条。
调试点： 后端是否能正确 Abort 前一个任务？前端是否清理上一轮的 Plan/Search 状态？
场景：空 Thought 返回 —— 直接给 Content。
调试点： 前端“思考过程”按钮是否自动消失。
场景：JSON 转义字符攻击 —— 模拟后端返回包含大量 \" 和 \n 的破坏性字符串。
调试点： 前端是否崩溃。
场景：历史记录重新渲染 —— 关闭页面重新进入，查看上述复杂场景的消息。
调试点： 验证历史记录接口返回的数据结构，前端能否完美复刻执行过程。
场景：Token 消耗预警 —— 当次对话消耗 10w Tokens。
调试点： 验证后端返回的 usage 信息在前端是否显示（或用于计费提醒）。
场景：极低网速模拟 —— 限制每秒接收 10 字节。
调试点： 观察前端 UI 组件（特别是 Plan Step）是否会因为数据不完整而频繁闪烁跳动。
