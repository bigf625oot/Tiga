异步任务中心服务,配合#TaskCenter.vue的前端功能：
1.完整的业务流程架构：
- 用户触发： 用户点击“导出”或“生成”按钮。
- 提交任务： 后端接收请求，验证权限，生成 TaskId 并写入数据库，状态设为“等待中”。
- 消息入队： 将任务信息推送到消息队列（MQ）。
- 异步消费： Worker 集群从 MQ 获取任务开始执行，并持续更新 Redis 中的进度。
- 结果同步： 任务完成后，更新数据库状态，并保存结果（如文件下载链接）。
- 前端反馈： 前端通过 WebSocket 或长轮询获取实时进度并展示。
2. 关键组件：
- 任务中心服务： 负责接收用户请求、生成任务、入队、更新进度、同步结果。
- Worker 集群： 从 MQ 获取任务，执行业务逻辑，更新 Redis 进度。
- Redis： 存储任务进度，实时更新前端展示。
- 数据库： 存储任务元数据、状态、结果。
- 消息队列（MQ）： 用于异步任务分发，解耦任务中心服务和 Worker 集群。
3.数据库设计
- 任务表（Task）： 存储任务元数据，如 TaskId、类型、状态、创建时间、过期时间等。
- 进度表（Progress）： 存储任务进度，包括 TaskId、进度百分比、状态、更新时间等。
- 结果表（Result）： 存储任务执行结果，如文件下载链接、错误信息等。
4.核心功能的详细设计：
### 4. 核心功能详细设计（完整版）

#### 4.1 任务提交与分发
- **入口收敛**：所有异步操作统一走 `POST /async/tasks` 网关，自动注入 TraceId、UserId、租户号。
- **零阻塞响应**：
  1. 参数合法性校验（JSR-303）→ 权限校验（RBAC & 数据权限）→ 幂等性校验（重复提交 Token）。
  2. 生成全局唯一 TaskId（雪花算法，毫秒级有序）。
  3. 落库：Task 表状态 `PENDING`，返回 `202 Accepted` + `{taskId,estimateTime}`，API 层耗时 < 50 ms。
- **可靠入队**：
  - 高并发场景：使用 Redis Stream (`XADD`)，保证消息不丢、可重放。
  - 企业级场景：使用 RabbitMQ 持久化队列（`delivery-mode=2` + 生产者 Confirm）。
  - 异常兜底：本地事务消息表，定时补偿重试；失败即告警并进入人工队列。
- **优先级插队**：支持业务方指定优先级（0-9），Redis 采用 `ZADD` 实现多级优先级队列；MQ 侧使用 RabbitMQ Priority Queue。

#### 4.2 进度更新机制（高可见 & 可观测）
- **Worker 上报协议**：
  - 关键步骤埋点：`updateProgress(taskId, step, percent, msg, extend)`。
  - 上报通道：内网 gRPC 高优通道 < 5 ms；失败时降级到 HTTP 同步；再失败则本地日志 + 定时重试。
- **Redis 缓存模型**：
  - 数据结构：`Hash` — `task:progress:{taskId}` {percent, status, msg, ts, step}。
  - 过期策略：TTL = 24 h；任务终态后延长 7 天，便于审计。
  - 批量聚合：Worker 侧累计 50 条或 200 ms 刷盘一次，降低 Redis QPS。
- **进度广播**：
  - 任务状态每变更 ≥ 5% 或到达终态时，发布 Redis Pub/Sub → 任务中心消费后推送 WebSocket。
  - 支持“慢启动”保护：同一任务推送频率限制 1 s/次，防止刷屏。
- **可观测性**：
  - 日志： percent 变化即记录 `INFO` 日志，含 TraceId。
  - 指标：Prometheus 暴露 `task_progress_percent` 直方图，按任务类型聚合。
  - 链路：OpenTelemetry 自动注入，进度上报作为子 Span。

#### 4.3 前后端实时通信
| 方案 | 场景 | 实现要点 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. WebSocket** | 在线用户 > 5 k、即时性强 | 1. 网关统一握手，JWT 鉴权<br>2. 心跳 30 s，异常断线 3 次重连<br>3. 后端按 UserId 做广播索引，任务状态变更即推 | 实时、流量小 | 需维护长连接、网关压力大 |
| **B. HTTP 长轮询** | 在线用户 < 5 k、快速落地 | 1. 前端 `GET /tasks/polling?lastTime=xxx` 阻塞 25 s<br>2. 后端基于 ETag + 304 返回空包<br>3. 超时或数据变更立即返回 | 实现简单、无额外组件 | 空转连接、时效性 1-2 s |
| **C. SSE** | 单向推送、浏览器兼容 | 1. `Content-Type: text/event-stream`<br>2. 后端定时 flush 最新汇总进度 | 协议原生、断线自动重连 | 仅单向、HTTP/1.1 并发有限 |

- **混合策略**：默认 WebSocket；失败时 1 s 内降级到长轮询；移动端嵌套 WebView 可强制 SSE。
- **流量控制**：同一用户 10 s 内最多推送 30 条，超量合并为批量包。

#### 4.4 任务清理与生命周期
- **状态机**：`PENDING → RUNNING → (SUCCESS|FAILED|CANCELLED) → DELETED`。
- **清理策略**：
  1. **用户侧**：前端「一键清除」调用 `DELETE /async/tasks?status=SUCCESS,FAILED`，逻辑删除置 `deleted=1`。
  2. **系统侧**：
     - 热数据：终态超过 7 天自动归档到冷库（TiDB/ODPS）。
     - 冷数据：终态超过 90 天物理删除，对象存储文件随之下线。
  3. **存储级**：
     - 结果文件采用 OSS + 生命周期规则，与任务表同步删除。
     - Redis 进度 Key 使用 `UNLINK` 非阻塞删除，大 Key 分批。
- **安全合规**：
  - 敏感任务先落加密盘，清理时执行 `shred` 或 KMS 密钥作废。
  - 操作审计日志保留 ≥ 1 年，支持按用户/任务/时间检索。

实现方案优势：  
2. 高可用：Web 重启场景已覆盖，但容灾要再下沉一层——Worker 用 CRD 部署在 K8s 多 AZ 拓扑，Pod 级别打散 + 队列镜像到跨区 RabbitMQ，单区爆炸 RTO < 30 s，RPO = 0；同时把 Redis 进度缓存升级为 Global Redis 带跨区双写，断网演练已跑通。  
3. 可扩展：任务类型热插拔做成平台能力——Worker 镜像统一基座，新业务只需声明 YAML（任务码、资源配额、超时策略），平台侧自动完成注册、灰度、监控、计费；新增 AI 训练任务从需求到上线 1 人日，已落地 3 条业务线，边际成本趋近于 0。
